# Skill evaluation for chefer (2026-10-17)

This document evaluates two community skill packs against chefer:

- **[mattpocock/skills](https://github.com/mattpocock/skills)** v1.3.1, installed as the plugin `mattpocock-skills@claude-plugins-official`.
- **[cursor/plugins › pstack](https://github.com/cursor/plugins/tree/main/pstack)** v0.15.25 by Lauren Tan ("poteto"), installed as the plugin `pstack@cursor-plugins`.

Both plugins are installed at **project scope**, recorded in `.claude/settings.json`. Neither ships hooks or MCP servers. The installed files are byte-identical to the upstream repos as reviewed.

The daily working pattern built on these findings is in [README.md](./README.md).

## How to read the scores

- **Useful (1–5):** how much the skill would help chefer if it fitted perfectly.
- **Fits (1–5):** how well it works as installed, given chefer's stack, rules and the Claude desktop app.
- **Verdict:**

| Verdict   | Meaning                                                                  |
| --------- | ------------------------------------------------------------------------ |
| **ADOPT** | Part of the daily loop.                                                  |
| **USE**   | Use it when the situation comes up.                                      |
| **ADAPT** | Keep the idea, port it into a chefer-owned skill or doc.                 |
| **LATER** | Revisit when a specific need arrives.                                    |
| **SKIP**  | Don't use it.                                                            |
| **NEVER** | Don't use it: it conflicts with a hard rule, such as "the owner merges". |

**Invocation names.** Plugin skills are namespaced. Type `/mattpocock-skills:<name>` or `/pstack:<name>`; the slash menu autocompletes. Most of these skills are **user-invoked only**: their frontmatter sets `disable-model-invocation: true`.

- **Matt:** only the owner can trigger 16 of his 27 plugin skills.
- **pstack:** only the owner can trigger 54 of its 55 skills.
- **Effect on agents:** an orchestrator or lane agent can't fire them through the Skill tool. Either you type them, or a brief tells the agent to read the skill file.

**Context cost.** Measured with `claude plugin details`, the always-on cost is about 1.2k tokens per session for Matt and about 3.2k for pstack. pstack's cost is mostly slash-menu entries, which add clutter rather than tokens. The real cost comes when a skill runs: a full `poteto-mode` Feature run reads 60–90 KB of instructions.

## 3. pstack: skills

**Cross-cutting caveats:**

- **The panels lose their second model.** pstack assumes mixed Opus and Grok panels. In Claude Code every Grok seat falls back to the session model, so "cross-model" reviews become Opus against Opus, and code delegates run on Opus rather than chefer's Sonnet lanes.
- **The Claude Code build isn't really translated.** It still contains Cursor tool names and paths. The model maps them at run time using `docs/harness/claude-code.md`.
- **Transcript miners miss worktree sessions.** `recall`, `automate-me`, `reflect` and `show-me-your-work` read only this workspace's folder in `~/.claude/projects/`, but chefer worktree sessions each have their own folder. On this machine that is 6 of 8 folders. Tell these skills to include `-Users-danpop-work-git-projects-chefer--claude-worktrees-*`.

## 4. pstack: `poteto-mode` and its 23 playbooks

`poteto-mode` is the front door. You type it, it matches your task to a playbook, copies that playbook's steps into the todo list, and pulls in other skills and principles as steps need them. The engineering ideas are excellent: reproduce first, pin behaviour before refactoring, prove it on the real artifact, leave resume notes, key verdicts to the head SHA.

As a vehicle for chefer it scores **Useful 3 / Fits 2**:

- It is Cursor-native and expects models from several vendors.
- It is heavy: each delegate re-reads 20 KB.
- Several playbooks merge PRs or poll CI.
- It knows nothing of chefer's parity, additive-API, OTA, DB-clone and lane limits.

`00-operating-rules.md` is already a leaner, chefer-specific version of Feature, Orchestrate and Opening-a-PR. **Steal individual playbooks; don't adopt the mode.**

| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :----: | :--: | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

## 6. Bottom line

The highest-value pieces, in order:

1. **Alignment before code:** `grill-with-docs` / `grill-me`, and `in-your-own-words` for small tasks.
2. **Turning repeated corrections into enforcement:** `correct` and `retro`.
3. **One scripted way to prove behaviour:** `create-verification-skill` → `/verify-chefer`.
4. **Protecting shipped mobile clients:** `blast-radius` on every API, schema or Prisma change.
5. **Disciplined debugging:** `diagnosing-bugs` plus the poteto Bug-fix playbook.
6. **Review against the WP spec:** Matt's `code-review` (Spec axis) next to the built-in `/code-review`.
7. **Context continuity across many sessions:** `ketchup`, `recall`, and pause/pickup.

Matt's pack fits better as installed: small, composable, harness-neutral. pstack has more raw ideas but is Cursor-shaped. Keep Matt's plugin enabled. Use the handful of pstack skills listed above, port its best playbooks into chefer-owned skills, then disable pstack. That last step is in the next-actions list in [README.md](./README.md).
