## 1. Goal

Turn three owner asks into data foundations. **Ingredients** become a curated, id-keyed catalogue whose numbers say
where they come from (`Verified` / `Estimated` / `Yours`), with private user rows, allergen and diet tags, admin
review, and recipe lines linked by id (so safety can look up allergens and own-recipe nutrition explains itself).
**Cardio** becomes complete: 30 catalogue entries, intervals, a real "Next time", stats and bests, routine slots, and
(behind a flag) a calorie range. **The exercise library** becomes governed: users request exercises instead of
creating them, trainers and admins author library entries, and existing custom exercises stay usable. User-visible
outcome: the owner can log a ride or a run properly, trust ingredient numbers, and never meet another
"`3 × 1 s @ 15 kg`" exercise.

## 5. Acceptance criteria (condensed)

- **UX-41** (L-INGR): AC1 every catalogue row on every surface shows `Verified`, `Estimated` or `Yours`; AC2 a private
  ingredient is visible only to its creator (two-account API test) and never AI-refreshed; AC3 per-100 g and per-unit
  values with the gram weight; AC4 nothing says "allergen-free" or "safe" (forbidden-copy lint on
  `ingredient-copy.ts`); AC5 admins filter `Needs review`, verify, tag and merge, and merges move linked lines; AC6
  deleting a used private row warns with the recipe count and offers Undo; AC7 no brands, barcodes or shared user rows
  (seed data test); AC8 picked lines store the id and a level-0 client's free-text lines still save and keep links.
- **UX-01/11/19/17 A1** (L-INGR): a line linked to `Granola` is flagged for tree nuts through the tag, unlinking falls
  back to the matcher (safety suite); the explain sheet's rows sum to the shown kcal (± 1 per line) and estimated rows
  carry `~`; a private ingredient created from the Log sheet is loggable in grams at once and invisible to others;
  imported units are canonical or visibly `Other`.
- **UX-42** (L-GYMDATA PR A): AC2 timer survives a kill offline; AC5 every Next-time row incl. the 10 % ceiling and "no
  effort → hold" (unit tests); AC7 at D-17's default no calorie number anywhere, with the flag on only a range, only on
  the summary, only with a body weight; AC9 30 entries, each with tracking type, cue and equipment; AC10 level-0/1
  bootstraps contain no cardio row and level-2 ones no `INTERVALS` row (contract test); a level-1 routine save keeps the
  stored cardio slots.
- **UX-43** (L-GYMDATA PR B): AC1 with the flag on a user sees no `+ Custom` and an empty search offers
  `Request “{q}”` in the Exercises tab and the workout picker; AC2 a requested exercise is loggable at once, online or
  offline, with no Why?/Next time/load; AC3 `Did you mean?` first; AC4 resolving moves history and routine slots and
  shows the exact message once; AC5 existing customs stay listed, usable, editable; AC6 `TRAINER`/`ADMIN` author,
  `USER` cannot (middleware test); AC7 the flag cannot turn on before the cardio catalogue and the gap pass exist (a
  release-checklist data test); AC8 an old binary's `createCustom` after enforcement gets the readable message
  (contract test); AC9 a `TRAINER` has the same premium state as a `USER`.
- **UX-06 A1** (L-GYMDATA): a 25-min treadmill run on an unplanned day marks it `Run` with a change notice; a manual
  `Long run` is never downgraded.
