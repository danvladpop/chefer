## 1. Goal

Lay every shared foundation (kit components, schema, contracts, routers, flags, nav) that waves 1–4 build on,
**and** ship five hotfixes that stop active harm before anything else lands. User-visible outcome: the app looks
almost unchanged, but five bugs are fixed (unsafe Replace/"what can I make" picks, next-week-shown-as-this-week,
the calorie ring hidden for goal-less non-trackers, the budget field no longer silently drops input, a safer chat
system prompt) and a `Settings` hub + Food/Gym pill exist for later waves to build into.

## 2. Prerequisites

None — this is the first wave, cut from `master` @ `f8f7f74`.

**Blocked-by-owner-decision:** none block wave 0. Feature flags (T-00.8) are built regardless of D-1/D-2 answers;
every flag defaults **off** until the owner answers (02-business-strategy.md §9). Owner answers: _to be filled in._

**Internal ordering:** T-00.15 (W0-C) calls the `findForWeek` repository method that T-00.10 (W0-B) creates. Either
sequence W0-B before W0-C, or have the W0-C agent stub `findForWeek` itself and let W0-B's PR overwrite it — confirm
with the orchestrator before both land the same file.

## 5. Acceptance criteria (condensed, by hotfix)

- **T-00.11 / B-34, B-46:** `whatCanIMake` never ranks an unsafe recipe (API test, egg-allergic vegetarian). `recipe.list({forTable:true})` drops unsafe rows. `replaceRecipe` on an unsafe id → `UNSAFE_FOR_TABLE` with the ingredient named; `acknowledgeConflict:true` on an own recipe succeeds (UX-01 AC13).
- **T-00.12 / B-31 interim:** goal-less, non-tracking user sees no ring/weight card/nudge/Snap on Today (UX-04 AC4).
- **T-00.13 / B-10:** free-tier budget field is visually locked; no value is ever accepted then dropped (UX-10 AC4).
- **T-00.14:** prompt snapshot test contains the guardrail and never "nutritional advice" (UX-22 AC3).
- **T-00.15 / B-13:** plan only for next week → Plan/Shop/Today on "This week" all show empty, never leak next week's plan (UX-08 AC2, AC9). `plan_shown.weekMatches` fires true.

## 6. Schema / API notes

All Now schema (S1–S17 in 04 §3) lands in this wave, **additive only** (production applies with
`prisma db push --skip-generate`): `DietaryPreferences` (plan shape, `safetyReviewedAt`, `excludeLabelDependent`),
new `SafetyReport`/`TargetChange`/`ConsentEvent` tables, `ChefProfile` (jobs incl. `TRACK`, training weekdays/kinds,
timezone, own-target fields, `targetSnapshot`), `User` (health-consent cache, email-default notice, terms cache),
`GymProfile` (vest, quiet-nudge, session length, reminder times, carry-over), `ChefReview` (proposal fields),
`AiCallLog` (provider, saved, `CURATED_PLAN`). Two email digests and the Sunday auto-plan default flip to `false`
**for new rows only**. No enum is removed or renamed. New router stubs: `safety`, `targets`, `training`, `privacy`
(registered, empty implementations). `profile.flags` returns `FeatureFlags` (all off by default);
`x-chefer-api-level` header wired but nothing yet requires it. `HEALTH_CONSENT_ENFORCE=off` at this point.
