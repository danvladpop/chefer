## Where each item lives (origin/master)

**F1, week default day.**

- **Mobile.** In `apps/mobile/src/features/shell/meals/meals-screen.tsx`, the `SegmentedControl` `onChange` (l.691–696) only calls `setWeekOffset`, and `selectedDay` (l.157) is never reset.
  - The rule we want already exists as `defaultDay(weekOffset)` in `apps/mobile/src/features/friends/add-to-week/add-to-week-logic.ts` l.33. It belongs in `@chefer/utils`, next to `week-default.ts`.
- **Web.** `apps/web/src/app/(dashboard)/meal-plan/page.tsx` keeps `?day` across weeks (l.137, l.151). The behaviour is the same, so the fix is needed there too for parity.
- **Tests.** `apps/mobile/tests/unit/shell-meals-screen.test.tsx` l.414 and `packages/utils/src/week-default.test.ts`. Web has `meal-plan/page.test.tsx`.

**F2, import review problem rows.**

- **Mobile.** Rows in `apps/mobile/src/features/recipes/video-draft-form.tsx` (l.319–410) only flag rows that have **no catalog link**. Rows that are linked but have a `problem` (`NO_DENSITY`, `NO_PORTION`, `BAD_UNIT`, `BAD_QTY`) show nothing.
  - **Gotcha:** the live lines skip empty or zero rows (l.162–166), so a live line's index is not the form row's index.
- **API.** It already returns `problem` per line (`ImportLineResolution`, `recipe-import.service.ts` l.96; `lineProblemSchema` in `packages/types/src/nutrition.ts` l.67). The per-problem copy exists too: `lineProblemCopy()` in `packages/utils/src/nutrition/picker.ts` l.84.
- **Web is the reference.** `apps/web/src/features/recipes/components/RecipeLinesEditor.tsx` shows `lineProblemCopy` per row and highlights the bad field.
- **Tests.** `apps/mobile/tests/unit/import-review.test.tsx`.

**F3, hero image.**

- **Mobile.** `apps/mobile/app/recipe/[id].tsx` l.191–197 and l.412–419. `heroHeight()` gives about 16:10.
- `apps/mobile/src/features/recipes/recipe-image.tsx` uses React Native `Image` with `resizeMode="cover"` and NativeWind `className`. It is **shared with cards and tiles**.
- **Sources.** Images are generated at 4:3 (`imagen.ts` l.33), and Cloudinary stores them at 800×600 `crop: fill`.
- **Root cause unknown.** The code should crop, not stretch. It has to be reproduced on a device first.
- **Web.** `recipes/[id]/page.tsx` l.516.

**F4, tab order.**

- **F6–F7, plan.**
  - **Plan row and section.** The row is `you/account-screen.tsx` l.48–56, and the section is `apps/mobile/app/profile.tsx` l.230+.
  - **Data.** `useIsPremium()` and `useEntitlement()`, with `PLAN_FEATURES` in `packages/types/src/plan-features.ts`.
  - **Upsell.** `apps/mobile/src/features/premium/` holds `PremiumSheet`, `openPremium(source)` and `nudge-cap`. The copy is `PREMIUM_PITCH_COPY` in `packages/utils/src/premium-pitch.ts`.
  - **Web.** It has a full `/premium` page with `PremiumComparisonTable` and `PlanFooterCard`.
  - **Docs.** `docs/plan-premium-tier.md`: its paywall principles, such as "demo on their data", are at l.432. The design boards are `docs/design/mobile/You.dc.html`.
  - **Upgrades are free today.** There is no payment, so the App Store "free for now" screenshots in `docs/app-store/ios/app-review-simulation-2026-10-01/` apply.

**F8–F9, sign-up passwords.**

- **Live sign-up path.** Prod has `onboardingV4` on, so accounts are created in `apps/mobile/src/features/onboarding-v4/account-v4.tsx`. That screen has an email field, **one** password field (`NEW_PASSWORD_FIELD_PROPS`, l.189–191; its l.37 comment says "no confirm field"), and `setToken` on success (l.60–66). The legacy `apps/mobile/app/(auth)/register.tsx` already has a confirm field, using `useConfirmPasswordError` (`src/features/auth/use-confirm-password`).
- **Already in place.** Prod builds carry `associatedDomains: webcredentials:<EXPO_PUBLIC_API_URL host>`, i.e. `chefer.duckdns.org` (`apps/mobile/app.config.js` l.96–106, l.142–144). The API serves `/.well-known/apple-app-site-association` for `45TS85YK89.com.popdan.chefer` (`apps/api/src/lib/well-known/well-known.ts`). It is **live**: 200 JSON, checked on 2026-10-17. Password fields use `newPassword` in non-dev variants (`src/features/auth/password-fields.ts`, UX-ACC-08).
- **Hypotheses for F8, to rank and test.**
  1. The email field sends `textContentType: 'emailAddress'` (`packages/ui-mobile/src/components/email-field-props.ts`). iOS pairs the save prompt with a `username` field, so on sign-up and login screens the account field should probably be `username`, keeping the email keyboard.
  2. The Show toggle flips `secureTextEntry` and drops the password context.
  3. The prompt fires only when the fields leave the view hierarchy after a successful submit, and the post-`setToken` navigation may not remove them.
  4. The build under test lacks the entitlement: a dev variant, or `EXPO_PUBLIC_API_URL` not set at build time.
- **Shipping and verification.**
  - A JS-only fix ships by OTA.
  - An `app.config.js` or entitlement change needs a **new binary**, which the owner builds.
  - Final proof is the owner's own iPhone on a production-signed build. The simulator can show the prompt only with associated-domains development mode.
- **Web.** `apps/web/src/features/auth/components/register-form.tsx` already has a confirm field and autofill tests (`auth-autofill.test.tsx`). Check that it uses `autocomplete="username"` and `new-password` on both fields.
- **Android.** `assetlinks.json` needs `ANDROID_CERT_SHA256`. Check that Google's save prompt works on Pixel_8 with the same fields.

- **Devices.** Only **one** session at a time drives the iOS simulator or the Pixel_8 emulator.

1. **Merge.** Merge each session branch into `feat/feedback-2026-10-17` as it reports done. S4 and S5 are the only pair likely to touch shared tests.
2. **Ladder.** Run the full ladder: `pnpm typecheck`, `pnpm lint`, `pnpm test`, and mobile contract tests. Run the Playwright mobile sweep if web layout changed. Run one Maestro pass over the meals, import, recipe, You and sign-up flows.

5. **Owner merges.** Afterwards, run `mattpocock-skills:retro` on the run.
