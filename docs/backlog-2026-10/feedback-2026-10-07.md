## FB7-01 — Gym "More" tab

**Found.** `apps/mobile/app/(gym)/_layout.tsx` has 4 tabs (Today, Routine, Exercises, Stats); Food has 5 with **More**
(`app/(food)/more.tsx`: AI Chef, Progress, My weeks, Household, Profile, Following, Settings, feedback card, legal links,
Sign out, version). Gym users can only reach Gym settings through the header gear. Web already shows **More** in both
modes (`bottom-nav.tsx` + `mobile-nav-drawer.tsx`), so this is a mobile-only gap.

**Fix.** Extract the More body into a shared `MoreScreen` component that takes mode-specific items, and add a 5th
`more` tab to the Gym layout (same icon, same Following badge). Gym items: Gym settings, Profile, Following, Settings,
Progress, then the shared feedback card, legal links, Sign out and version. Food keeps its list unchanged.

## FB7-02 — Sign out on the profile's "Your data" card

**Found.** Mobile `AccountDataCard` (`features/profile/account-data-card.tsx`) and web `AccountDataCard.tsx` hold
Export + Delete. Sign out exists only in More / Settings (mobile, via `useSignOut` with a confirm sheet, including the
"unsynced workouts" warning) and in the web header user menu.

**Fix.** Add a **Sign out** button to the card on both platforms, between Export and Delete. Mobile reuses
`useSignOut('profile-sign-out-confirm')` (same confirm sheet and unsynced-workout guard). Web reuses `useAuth().logout`.
Neutral style (outline), not destructive red; Delete stays the only red action.

## FB7-03 — Import via link: overlapping text

**Found.** The screenshot shows the old "Ingredients to check" card (`import-line-review.tsx`), where
`IngredientPickerField`'s `flex-1` root sat in a column and its 44 pt "Change" button overlapped the line above. That
card was **removed on master on 2026-10-03** (ff72d449, "editable import review"): link, text and video imports now
share `video-draft-form.tsx` (mobile) / `VideoDraftForm.tsx` (web), where the picker sits in a row. The tester's build
predates that, or the OTA did not reach it.

**Fix.** Verify, don't rewrite. Lane s audits the current form for the same failure class (`flex-1` picker in a
column parent, long ingredient names, unit errors, 320 pt width and large text) and fixes anything it finds. It adds a
Jest test that renders a row with a long name plus a unit error, and the Playwright mobile sweep covers the web
sheet. At integration, the orchestrator imports the same recipe on the iOS simulator and attaches a screenshot to the PR.

## FB7-04 — Two recipes in one meal (meat + side)

**Tester's question:** should the functionality change, or should they merge the two recipes into one? **Answer: the
app should support it; don't merge recipes.** A main plus a side is normal cooking, and merging breaks reuse of each
recipe.

**Found.** A day's plan is a flat array of slots (`MealPlanDay.meals`, ≤ 10). Each slot holds one recipe, and several
slots may share a meal type. `recipe.addToWeek({ mode: 'add' })` → `mealPlanService.addRecipeToSlot` already appends a
pinned slot of a given type. It is only reachable from a recipe's detail page ("Add to week"), which the tester didn't
find from the plan.

**Fix (no schema change).**

1. Add an **"Add a side dish"** entry to each plan meal's action menu (see FB7-11). It opens the existing recipe
   picker and calls `recipe.addToWeek({ mode: 'add', day, mealType })` for that day and meal type.
2. Render same-type slots of a day as **one meal group**: a single "LUNCH" header, then the main card and a compact
   side card ("+ side"), plus a group total (kcal + macros). Each card keeps its own actions (swap, remove, portion).
3. Add **Remove from plan** on a side slot. It needs a small additive `mealPlan.removeSlot({ weekOffset/planId, day,
slotIndex })` procedure if none exists; the lane checks `undoAddToWeek` first.
4. Day totals, the tracker ("Log lunch" logs each dish) and the shopping list already iterate slots, so the side's
   ingredients and macros count automatically. Lane p adds tests asserting this.
5. Copy on the "Add to week" sheet: "Add as a side" / "Replace this meal" instead of the raw add/replace.

## FB7-05 — Underlined exercise names

**Found.** `ExerciseNameLink` (`apps/mobile/src/features/gym/components/exercise-name-link.tsx`) defaults to
`underline decoration-dotted`. It is used on the summary (PRs, Next time), Today "Next up" and the setup preview. Web
renders plain names.

**Fix.** Default `underline` to `false`. The name stays tappable with a 44 pt hit area and `accessibilityRole="link"`
plus a hint. Glossary terms (`glossary-term.tsx`) are a different affordance and keep their dotted underline. Update the
Jest snapshot/tests.

## FB7-06 — Every exercise has a photo and a video

**Found.** The catalog (`packages/types/src/gym/exercise-catalog.ts`) has **191** exercises:

| Missing              | Exercises |
| -------------------- | --------- |
| Photo                | 119       |
| Video                | 114       |
| Both photo and video | 111       |

Most of the gaps are the 91 rows added on 2026-10-02, which shipped media-less **by owner decision L-D1**. Photos come
from free-exercise-db (doubtful licence), and the owner said they would source replacements themselves.

**Fix.**

  uses (`videoChannel` values). Fill `videoId` / `videoStartSec` / `videoChannel` and verify every id with the existing
  oEmbed checker (`scripts/gym/check-exercise-videos.ts`). No id may be added unverified. Add a catalog test that
  every non-hidden exercise has a `videoId`, so a future row can't ship without one.
- **Photos: owner decision needed (FB7-06-Q).** Options:
  - (a) use free-exercise-db photos for the new rows too, the same source as the 72 rows the owner kept on 2026-10-02
    (candidate ids are already in `docs/gym/library-expansion/sources.json`);
  - (b) keep waiting for the owner's replacements;
  - (c) generate one consistent illustration set for **all** 191 exercises (no licence question, one style).

  Lane v implements whichever the owner picks. Until then, the library shows the muscle-group icon placeholder (as
  today), and the gap report lists exactly which exercises still lack a photo.

## FB7-07 / 08 / 09 — Pill filters

**Found.**

- Exercises tab (`library-screens/exercises-tab.tsx`, `CollapsibleChipFilters`) shows three rows: muscles, "Mine" and
  equipment. Web has two rows.
- Stats "Weekly sets per muscle" (`stats/muscle-volume-view.tsx`) uses a wrapping `ChipGroup` with 12 options in 4 rows.
- Stats "PR timeline" (`stats/pr-timeline-view.tsx`) has one chip per exercise, wrapping into 10+ rows.
- Web stats already uses a `<select>` for both.

**Fix.**

- **Exercises (mobile + web): one row.** A single horizontally scrolling row:
  1. an **Equipment ▾** chip that opens a `SelectSheet` (shows the chosen value, e.g. "Dumbbell ▾");
  2. a **Mine** toggle chip;
  3. then the muscle chips.

  The active-filter count shows on the Equipment chip, and a "Clear" chip appears when any filter is set. The same
  `CollapsibleChipFilters` change applies to the exercise picker (it shares the component). Web gets the same single
  row (Equipment as a select-styled chip).

- **Weekly sets per muscle (mobile): dropdown.** Replace the chips with a `SelectField` ("Muscle: Chest ▾"), matching
  web.
- **PR timeline (mobile): dropdown with search.** Replace the chips with a `SelectField` ("Exercise: All ▾", searchable
  when there are more than 12 options), matching web.

## FB7-10 — Shop: no "In my kitchen", no AI, real images

**Found.**

- The list is **already computed from the plan's recipes** (`shopping-list.service.ts` `buildDerivedRawItems` →
  `aggregateIngredientLines`). AI is only the optional premium "Regenerate with AI" tidy-up. Its stored result
  (`aiGenerated=true`) then replaces the derived list, which is what reads as "AI-generated".
- "In my kitchen" is the pantry (`PantryItem`). Ticking an item seeds it, and `applyPantry` marks items "Have it" and
  subtracts them.
- Item images come from `resolveIngredientImage(name)`: a cache, then Unsplash (no key on prod), then a Pollinations
  generated URL. 1088 of 1090 catalog ingredients have no image of their own. Cold Pollinations renders often fail or
  time out on the phone, which leaves the blank thumbnails in the screenshot (Strawberries, Raspberries).
- The default week flips to next week from Friday 15:00.

**Fix.**

1. **Remove "In my kitchen"** (mobile + web): the segmented control, the pantry panel, the pantry check / ghost /
   usage banners on Shop, and the `/pantry` entry points (the routes redirect to Shop). On the server, the shopping
   list stops applying the pantry (`applyPantry` off) and ticking stops seeding it, so nothing is silently marked
   "Have it". Pantry tables and procedures stay (additive-only API; old clients keep working). The plan prompt's
   "use-first" pantry hint becomes a no-op.
2. **No AI on the list** (mobile + web): remove the "Regenerate with AI" button. `getForWeek` always serves the derived
   list (custom items and ticks preserved by canonical key), so weeks that were AI-tidied before go back to the
   computed list. `shoppingList.regenerate` stays for old clients but returns the derived list.
3. **Clear provenance copy** under the title: "From your plan's recipes · Mon–Sun" (the existing window label), so it's
   obvious where the list comes from and which days it covers. Next-week behaviour is unchanged (flips Friday 15:00;
   the week arrows still work).
4. **Images, two layers.**
   - **Lane s (client):** a thumbnail that fails or has no URL shows the aisle icon on a tinted tile, never a blank
     box. Mobile `Image` `onError` and web `onError`.
   - **Lane i (data):** a backfill script `scripts/ingredient-images/backfill.ts` gives every catalog ingredient (and
     every name in the image cache) a **stable hosted image**. It renders the deterministic product-shot prompt (the
     existing `PROMPT_OVERRIDES`), uploads it to Cloudinary (existing `CLOUDINARY_*` env, already used for recipe
     images), and writes the Cloudinary URL to the `IngredientImage` cache. It also produces a contact-sheet HTML for
     visual review, with `--dry-run` and `--only <names>`. Run on dev in the PR. Running it on prod is an owner/ops
     step: the orchestrator runs it over `ssh chefer` after merge, with the owner's OK.
5. The estimated total stays on Shop (the tester only asked to drop the price on the Plan page).

## FB7-11 — Plan page UX

**Found** (`app/(food)/meal-plan.tsx`, `plan-meal-card.tsx`, `meal-card-view.tsx`; web `meal-plan/page.tsx`,
`day-view.tsx`, `MealCard.tsx`):

- The cost line "≈ 308–416 RON · Wed–Sun" sits next to **Regenerate**.
- **Rebalance my week** is a separate button.
- Each card is image | body | three fixed-width icon columns (pin, swap, "…"). The right side eats about 40% of the
  width.
- Cards show kcal only.

What the two actions do:

- **Regenerate** builds a new week of meals and keeps the meals you pinned.
- **Rebalance my week** swaps up to 2 upcoming meals for safe curated ones, to bring the week back on target after a
  day over or under. It uses no AI.

**Fix (mobile + web).**

1. **Remove the price line** from the Plan page. Cost stays on Shop.
2. **One "Week options" menu** replaces the two buttons. It is a button with a sliders/"…" icon next to the week
   header, opening a sheet with two described actions:
   - "New meal plan for this week — keeps your pinned meals" (Regenerate, same confirm as today);
   - "Rebalance my week — swaps up to 2 upcoming meals to get your week back on target" (the existing preview/apply
     flow).

   Rebalance also shows inline as a banner **only when** `previewRebalance` finds something to fix (the existing
   tracker banner logic), so the user isn't asked to guess.

3. **Card layout:**
   - image (fixed) | body (`flex-1 min-w-0`, gets the space back) | **one** compact action column;
   - body: type badge, name (2 lines), then a meta line "10 min · 687 kcal", then a **macro line** "P 32 g · C 60 g ·
     F 18 g" from `meal.recipe.nutritionInfo` × portion (protein-only mode shows protein only, as today);
   - the "AI-generated" chip shrinks to a small sparkle icon in the meta line (with an accessibility label);
   - actions: **swap** stays one tap (the most used action), and **pin, Ate something else, Skip, Add a side dish,
     Remove** move into the single "…" menu;
   - a pinned meal shows a small bookmark badge on its image instead of an always-visible bookmark button.

   Touch targets stay 44 pt; the card height does not grow.

4. Training-day banner, day pills and week header are unchanged.
