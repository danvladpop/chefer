## C. T-12 AC3: analytics proxy check (owner, on a phone)

**Goal:** prove that with "Send anonymous usage counts" **off**, a full session makes **zero**
requests to `eu.i.posthog.com`.

### What is verified at code and test level

- No key, no traffic: `analytics-transport.ts` sets `enabled` only when both `EXPO_PUBLIC_POSTHOG_KEY`
  and `EXPO_PUBLIC_POSTHOG_HOST` are set; otherwise `enqueue` stores nothing and `flush` returns
  before `fetch`. Test: `apps/mobile/tests/unit/analytics.test.ts`, "no key configured = the
  transport is disabled and never queues or fetches".
- Off before the event: `track()` returns before `enqueue` when `consent.anonymous` is false. Test:
  same file, "AC3: turning anonymous counting off means fetch is never called".
- Off also turns linking off, and sign-out resets linking: same file.
- **Gap found, not fixed (app code):** if an event is queued while counting is on and the user then
  turns it off, the queued batch is still sent at the next 30 s flush or when the app goes to the
  background, because `flush()` does not check consent and `setAnalyticsConsent()` does not clear
  the queue. Recorded as `it.failing` in `apps/mobile/tests/unit/analytics-optout-queue.test.ts`
  (it passes while the gap exists and fails the day the queue is dropped on opt-out; then change it
  to a plain `it`). The proxy run below includes a step that shows it on a real phone.
- **Second gap:** `setCurrentUserId()` is never called, so "Link usage to my account" has no effect
  today (events always carry the random session id).
- The build carrying the check needs a **test** PostHog key. On a normal production build the
  variables are unset and the result is trivially zero; that is the current state of the store build.

### Procedure

Preconditions: a laptop and the phone on the same Wi-Fi; mitmproxy or Charles with its certificate
installed and trusted on the phone; a **development or preview** build (never the App Store build)
made with `EXPO_PUBLIC_POSTHOG_HOST=https://eu.i.posthog.com` and `EXPO_PUBLIC_POSTHOG_KEY=<a key
from a throwaway PostHog project>`. Do not put that key in `apps/mobile/.env` used for production
builds. Set the proxy filter to `host contains posthog`.

| Step | Do                                                                                                                                                                                                                                                                                      | Expect                                                                                                                                                         | Pass / fail |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| 1    | Fresh install, sign in. Leave "Send anonymous usage counts" **on**. Open Plan, Shop, Gym Today. Wait 40 s, then send the app to the background.                                                                                                                                         | At least one `POST https://eu.i.posthog.com/batch/`, body `api_key` + `batch` with typed events, `distinct_id` a UUID that changes after force-quit and reopen |             |
| 2    | Look at every property in the body.                                                                                                                                                                                                                                                     | Only counts, booleans, enum strings; no email, name, allergy, weight, food or message text                                                                     |             |
| 3    | Profile › Privacy & data › Usage analytics: turn "Send anonymous usage counts" **off**. "Link usage to my account" becomes disabled and off.                                                                                                                                            | No request for the change itself                                                                                                                               |             |
| 4    | Clear the proxy log. Scripted session of about 3 minutes: force-quit and reopen, browse Today, Plan (Regenerate, Replace, pin), Shop (tick, share), Recipes, Cook mode, Gym (start a workout, log 2 sets, finish), Profile, More; background for 60 s and return; sign out and back in. | **Zero** requests to `eu.i.posthog.com`                                                                                                                        |             |
| 5    | (Shows the known gap) Turn counting **on**, tap a few screens, and within 20 s turn it **off**; wait 60 s and background the app.                                                                                                                                                       | Ideal: zero requests. Today: probably one batch containing the events queued before opt-out                                                                    |             |
| 6    | Toggle off, force-quit, reopen.                                                                                                                                                                                                                                                         | Still off (the choice is stored in the local KV); zero requests at launch                                                                                      |             |
| 7    | Record the result and the mitmproxy log file in the release notes.                                                                                                                                                                                                                      |                                                                                                                                                                |             |

Steps 3, 4 and 6 must pass for AC3. Step 5 is expected to fail until the app code drops the queue
on opt-out.

## E. V9: VoiceOver (iOS) and TalkBack (Android) hardware script

Run on a real device, one pass per platform, with the Release/preview build that will ship. Use a
Free demo account (not the reviewer's). Turn on **VoiceOver** (Settings › Accessibility) or
**TalkBack** (Settings › Accessibility), and repeat the flagged rows with **text size at the
largest setting** (iOS Larger Accessibility Sizes AX5 / Android font size and display size at max).
For each row record `P` (pass) or `F` (fail, with a note) in the platform column. A pass means:
every control is reachable by swiping, has a spoken name and role, state changes are announced,
focus moves into and out of sheets, nothing is clipped at large text, and nothing needs sight to
complete.

Universal checks on every screen: one heading is read first; the tab bar and the Food/Gym switch
read as "selected"; no unlabeled button; Back and close work with the screen reader gestures.
